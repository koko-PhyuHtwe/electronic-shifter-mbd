## 1. 项目概述

本项目搭建一套 **线控换挡（Shift-by-Wire, SBW）系统** 的 HIL（硬件在环）双控制器原型，模拟真实车辆"决策-执行"分离的换挡电子架构，覆盖 **模型开发 → 自动代码生成 → 嵌入式落地 → 双 ECU CAN FD 通信 → 电机执行闭环** 的完整研发流程。

- **目标**：从 Stateflow 状态机到真实双 MCU 的完整系统跑通，作为求职简历的核心项目。
- **两大 MCU 分工**：
  - **NXP S32K144**：采集 + 决策层。读取摇杆/刹车/按键等 ADC/GPIO 输入，运行换挡状态机，通过 CAN FD 向 G474 下发换挡指令。
  - **STM32G474VET6**：执行 + 反馈层。接收换挡指令，驱动换挡电机动作，采集位置传感器，向 S32K144 反馈实际档位与执行状态。
- **操作系统**：双端均采用 **FreeRTOS**。
- **通信**：**CAN FD**（仲裁段 500kbps + 数据段 2Mbps）。

## 2. 系统架构

```
       S32K144（采集 + 决策 / 主节点）                              G474（执行 + 反馈 / 从节点）
┌────────────────────────────────────────┐      CAN FD       ┌────────────────────────────────────────┐
│ 摇杆 X/Y  ── ADC（板载电位器）          │                     │  CAN FD 接收 0x180（目标档位）          │
│ 刹车踏板  ── ADC                        │  0x180 目标档位      │  FreeRTOS 任务                         │
│ P/解锁/valid ── GPIO                    │ ▸▸▸▸▸▸▸▸▸▸▸▸▸▸▸▸▸▶│   电机控制（FOC / PWM）                  │
│ 车速/转速 ── 模拟/外部输入              │                     │   位置传感器采集（霍尔/旋变）            │
│                                        │                     │   实际档位判断                          │
│  GearShift_Stateflow_step()            │  0x280 实际档位/状态  │                                        │
│  输出 current_gear                     │ ◂◂◂◂◂◂◂◂◂◂◂◂◂◂◂◂◂│   回发 actual_gear / fault             │
└────────────────────────────────────────┘      CAN FD       └────────────────────────────────────────┘
              决策端（主）                                               执行端（从）
```

- **S32K144**：板载电位器直接采集摇杆；跑换挡状态机；下发目标档位；根据 G474 回传的实际档位做仲裁。
- **G474**：接收目标档位指令，控制换挡电机动作，读取位置传感器，判断实际档位，回传状态。
- 通信链路同时可供 **CANoe / PCAN-View** 监听，用于 HIL 调试验证。

## 4. CAN FD 通信协议

### 4.1 S32K144 → G474：目标档位报文 `0x180`（DLC=8）

| 相对偏移 | 信号 | 类型 | 说明 |
|---|---|---|---|
| 0 | `target_gear` | uint8 | P=0 R=1 N=2 D=3 M1=11…M6=16 FAULT=255 |
| 1 | `target_gear_display` | uint8 | 同上 |
| 2 | `reserved` | uint8 | 0 |
| 3 | `reserved` | uint8 | 0 |
| 4 | `reserved` | uint8 | 0 |
| 5 | `reserved` | uint8 | 0 |
| 6 | `reserved` | uint8 | 0 |
| 7 | `reserved` | uint8 | 0 |

- **字节序**：统一 **小端 little-endian**。
- **校验**：CAN FD 硬件自带 ECC；如需更高可靠性，可在字节 7 加 CRC8（后续扩展）。
- **超时保护**：G474 若 100ms 未收到 0x180，则保持当前实际档位并报通信丢失故障。

### 4.2 G474 → S32K144：实际档位与执行状态报文 `0x280`（DLC=8）

| 偏移 | 信号 | 类型 | 说明 |
|---|---|---|---|
| 0 | `actual_gear` | uint8 | 实际机械档位，编码同 target_gear |
| 1 | `actual_gear_display` | uint8 | 同上 |
| 2 | `exec_state` | uint8 | 0=Idle 1=Moving 2=Reached 3=Fault |
| 3 | `fault_code` | uint8 | 0=None 1=Timeout 2=Block 3=SensorErr |
| 4·5 | `motor_position` | uint16 | 电机位置或传感器原始值 |
| 6 | `reserved` | uint8 | 0 |
| 7 | `reserved` | uint8 | 0 |

## 5. FreeRTOS 任务划分

### 5.1 S32K144
| 任务 | 周期 | 内容 |
|---|---|---|
| `Task_ADC_GPIO_采集` | 10ms | 摇杆/刹车 ADC + 按键 GPIO 读取 |
| `Task_Stateflow_决策` | 10ms | 调 `GearShift_Stateflow_step()`，得到 target_gear |
| `Task_CAN_Tx` | 20ms | 发送 0x180 目标档位 |
| `Task_CAN_Rx` | 事件 | 接收 0x280 实际档位与状态 |
| `Task_仲裁_超时` | 50ms | target 与 actual 比对，超时或执行失败进 FAULT |

### 5.2 STM32G474VET6
| 任务 | 周期 | 内容 |
|---|---|---|
| `Task_CAN_Rx` | 事件 | 收 0x180，解析 target_gear |
| `Task_Motor_Control` | 1ms / 10ms | 根据目标档位驱动电机（PWM/FOC） |
| `Task_Position_Sense` | 10ms | 读位置传感器，判断 actual_gear |
| `Task_CAN_Tx` | 20ms | 发送 0x280 实际档位与执行状态 |
| `Task_Fault_Detect` | 50ms | 堵转、超时、传感器异常检测 |

> 关键：S32K144 上直接复用 MATLAB 生成的 `GearShift_Stateflow_step()`，输入来自本地 ADC/GPIO，输出 target_gear 通过 CAN FD 下发给 G474。

## 7. G474 端推荐用法说明

| 层级 | 推荐做法 | 价值 |
|---|---|---|
| **阶段一：开环 PWM** | H 桥驱动直流/减速电机，正反转对应升/降档方向 | 快速验证电机和执行机构能动作 |
| **阶段二：位置反馈** | 加霍尔/编码器，判断实际档位，回传 0x280 | 闭环雏形，双 ECU 真正联动 |
| **阶段三：FOC 闭环** | 若换挡电机是 PMSM，用 FOC + SVPWM 精确控制 | 简历电机驱动亮点，控制精度高 |
| **阶段四：故障诊断** | 堵转检测、执行超时、传感器异常 → 报 DTC | 符合车规 ECU 安全要求 |

> 推荐路线：**先开环 PWM 让电机动 → 加位置传感器做反馈 → 最后考虑 FOC**。不必一开始就做 FOC，先把 144↔G474 的 CAN FD 链路跑通是最关键的。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 两端字节序不一致导致解析错乱 | 统一小端，联调用报文比对 |
| CAN FD 波特率/收发器不匹配 | 仲裁 500k + 数据 2M，选 3.3V 收发器 |
| G474 执行超时未完成换挡 | S32K144 端 target vs actual 仲裁，超时进 FAULT |
| RTOS 任务栈溢出 | CAN/状态机任务栈给足 512~1024 字 |
| 摇杆 ADC 抖动导致误触发 | 软件滤波 + 阈值滞后（如 0.3V/2.7V/1.5V 三档判断） |
| 手自挡进出方向混淆 | 以本文档 §3.3 的 X/Y 轴定义为准 |

## 9. 简历价值总结

- **MBD 全流程**：Stateflow → Embedded Coder → 嵌入式 C → 真实 MCU。
- **汽车电子架构**：决策-执行分离、双 ECU CAN FD 通信、FreeRTOS 多任务。
- **硬件能力**：S32K144 采集/决策、STM32G474 电机驱动/位置反馈、ADC/GPIO/CAN FD 收发器。
- **车辆功能**：SBW 换挡状态机、逐级换挡、自锁防连跳、故障保护、手动挡升降档保护。
- **可选加分项**：FOC 电机控制、UDS 诊断、CANoe 测试验证。
