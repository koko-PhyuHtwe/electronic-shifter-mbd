# BMW Shift-by-Wire HIL

**双 ECU 线控换挡硬件在环原型** —— 摇杆 → 换挡状态机 → CAN → 舵机 / 电机，全链路跑在真实硬件上。

不是仿真，不是单板实验：两片 MCU、真实 CAN 总线、真实执行机构，带互锁、故障降级和动力切断。

```
                 ┌──────────────────────────┐        ┌──────────────────────────┐
   摇杆/踏板/按键 │      S32K144 (采集+决策)  │  0x180 │     STM32G474 (执行+反馈) │
   ─────────────►│  ADC → 校准 → Stateflow  │ ─────► │  档位 → 角度 → PWM       │──► 舵机
                 │  8 个输入 → 换挡决策      │ ◄───── │  0x280 回报实际位置      │──► 电机(电调)
   串口屏 HMI ◄──│  UART 演示面板            │  0x280 │  超时冻结 / 拒绝执行      │
                 └──────────────────────────┘  500k  └──────────────────────────┘
```

## 核心信息速查

| 项目 | 值 |
|------|-----|
| 采集/决策 MCU | NXP S32K144（Cortex-M4F，80 MHz，FreeRTOS） |
| 执行/反馈 MCU | STM32G474VET6（Cortex-M4F，170 MHz，FreeRTOS） |
| 总线 | Classic CAN，**500 kbps** |
| 报文 | `0x180` S32K→G474（8 B）/ `0x280` G474→S32K（8 B） |
| 换挡模型 | Simulink/Stateflow **v1.24**，10 ms 定步长，ert.tlc 生成 |
| 档位编码 | `0`=P `1`=R `2`=N `3`=D `11~16`=M1~M6 `255`=FAULT |
| 舵机角度 | P 0° / R 36° / N 72° / D 108°（脉宽 500~2500 µs @50 Hz） |
| 通信超时 | 两侧均 500 ms；S32K 连续超时 **2 s** 进 FAULT |
| 执行侧看门狗 | IWDG 1.25 s |
| 采集侧看门狗 | WDOG 1.0 s（**代码就绪，当前关闭**，见 `rtos.c` `WDOG_ENABLE`） |

## 快速上手

### 1. 接线

- CAN_H / CAN_L 接到两端收发器，**两端各 120 Ω 终端电阻**（60 Ω 是正确值，量到 60 Ω 只证明线通，不证明收发器活着）
- 舵机三线：信号→PE2，电源→独立 5 V，地→**必须与板子共地**
- 电调：信号→PE3，黑线共地，**BEC 红线不要并到板子 5 V**
- 摇杆电位器：两端 3.3 V / GND，中抽头→PTC2/PTC3。**GND 一定要接**，否则读数会"必须同时推两个轴才有反应"

### 2. 烧录 S32K144

用 S32DS 打开 `S32K144/freertos_s32k144/`，编译 `Debug_FLASH` 并下载。

只想验证语法、不开 IDE：

```powershell
cd S32K144/freertos_s32k144/Debug_FLASH
& "E:\NXP\S32DS.3.6.8\S32DS\build_tools\gcc_v11.4\gcc-11.4-arm32-eabi\bin\arm-none-eabi-gcc.exe" `
  "@src/GearShift_Stateflow.args" -o out.o ..\src\rtos.c
```

### 3. 烧录 G474

用 Keil/CubeIDE 打开 `STM32G474VET6/ShiftByWire_HIL/` 编译下载。

### 4. 上电顺序

先给 G474 上电，再给 S32K 上电（反过来也能跑，S32K 会先发几帧无人应答，FlexCAN 自动 bus-off 恢复）。

**上电后等 1 秒再动摇杆** —— 这段时间在采集回中基准，摇杆被强制判中位。

## CAN 协议

### `0x180` S32K → G474（10 ms）

| 字节 | 含义 | 说明 |
|------|------|------|
| B0 | `target_gear` | 目标档位 |
| B1 | `gear_display` | 同 B0，供屏幕显示 |
| B2 | 保留 | 0 |
| B3 | `life_counter` | 每次发送 +1，用于对端检测重启 |
| B4 | `vehicle_speed` | km/h，上限 240 |
| B5 | `motor_throttle` | 0~100 %，执行侧限幅 60 % |
| B6 | `brake_pct` | 0~100 %，刹车优先用 |
| B7 | 保留 | 0 |

### `0x280` G474 → S32K（10 ms）

| 字节 | 含义 |
|------|------|
| B0 | `actual_gear`（舵机真正到位后的档位） |
| B1 | `servo_angle_deg`（0~108） |
| B2 | `status` 位域 |
| B3 | `life_counter` |

### 状态位（B2）

| 位 | 名称 | 含义 | 屏幕显示 |
|----|------|------|---------|
| bit0 | `COMM_TIMEOUT` | 0.5 s 没收到 0x180，执行侧冻结 | `CAN LOST` |
| bit1 | `SHIFT_REFUSED` | 对端行驶中重启过，拒绝 P/R | `EXEC LOCK` |
| bit2 | `INVALID_CMD` | 收到非法档位码（如 255），保持不动 | — |
| bit3 | `MOTOR_CUT` | 动力被软切（失联/FAULT） | `PWR CUT` |
| bit4 | `GEAR_INHIBIT` | 当前档位不给动力（P/N/R） | `NO DRIVE` |
| bit5 | `BRAKE_CUT` | 刹车优先，油门被切断 | `BRAKE CUT` |

## 换挡逻辑（模型 v1.24）

上电**必定进 P**。出 P 需要四件事同时成立：

```
解锁键 + 刹车 > 30% + 车速 < 5 km/h + 摇杆回中过（消抖沿）
```

| 过渡 | 条件 |
|------|------|
| P → D | 上述四条件 + 摇杆前推 |
| P → R | 上述四条件 + 摇杆后拉 |
| N → D | 摇杆前推（不需解锁/刹车） |
| N → R | 摇杆后拉 + 车速 < 5 |
| D → N | 摇杆后拉 |
| R → N | 摇杆前推 + 车速 < 5 |
| D → M | 摇杆右推 |
| M → D | 摇杆左推 |
| D/M → P | P 键 + 刹车 > 30 + 车速 < 5 + **油门 = 0 且车速 = 0** |
| FAULT → P | P 键 + 刹车 > 30 + 车速 < 5 + 摇杆回中 |

**M 挡自动升降**（进入 M 时按车速选 M1~M6）：

- 升挡：`rpm > 6500`，或 `摇杆后拉 && rpm ≥ 2000 && 车速 ≥ 25/50/80/120/160`
- 降挡：`rpm < 1200`，或 `摇杆前推 && 车速 ≤ 15/40/70/100/140`

这些门限来自仿真标定：6 挡 240 km/h 对应 5485 rpm，红线 6800，正好留有余量。

**换挡规则只写在模型里。** `rtos.c` 只做字段映射，不做二次屏蔽 —— 一条规则只有一个出处，重新生成不会分叉。

## 安全机制

### 四级防线

| 级别 | 位置 | 动作 | 时间 |
|------|------|------|------|
| 1 | G474 通信超时 | 舵机**保持不动**（不归位、不乱动） | 0.5 s |
| 2 | S32K 通信超时 | 进 FAULT，只允许人工确认退回 P | 2 s |
| 3 | G474 IWDG | CPU 卡死则复位，恢复通信 | 1.25 s |
| 4 | S32K WDOG | 五任务活体不推进则复位（当前关闭） | 1.0 s |

### 两个锁存

- **EXEC LOCK**：行驶中 S32K 重启 → G474 检测到车速单帧暴跌或生命计数不连续 → **拒绝任何 P/R 指令**，断开重连不解除，必须断电。
- **PWR CUT**：通信丢失或 FAULT → 电机 200 ms 内斜坡归零并锁存，必须松脚重踩才恢复。

### 动力六道门（按顺序全过才给油门）

```
3 s 解锁等待 → 见过 B5==0 → 软切未锁存 → 档位 ∈ D/M1~M6 → 刹车 ≤ 5% → 限幅 60%
```

**同一个故障，两个执行机构策略相反**：舵机失联保持不动（乱动更危险），动力失联立刻归零（不停更危险）。

## 演示（5 分钟）

1. **换挡链路**（40 s）：摇杆前推 P→D，舵机转到 108°；右推进 M，踩油门自动升 M1→M2→M3
2. **互锁**（30 s）：不按解锁 → `NEED UNLOCK`；不踩刹车 → `NEED BRAKE`；车在动按 P → `STOP FIRST`
3. **通信故障**（50 s）：拔 CAN → `CAN LOST` → 2 s → `FAULT` → 手推舵机推不动 → 插回 → 手动确认才恢复
4. **动力安全**（50 s）：P 挡轰油门不转（`NO DRIVE`）；D 挡转；踩刹车 → `BRAKE CUT`；拔 CAN → `PWR CUT`
5. **重启锁存**（30 s）：行驶中复位 S32K → `EXEC LOCK`，执行侧拒不动

#### 屏幕控件

| 控件 | 内容 |
|------|------|
| `t0` | 大号档位 `P/R/N/D/M1..M6/FAULT` |
| `t1` | 状态行（`NEED BRAKE` / `CAN LOST` / `PWR CUT` …） |
| `n0`~`n5` | 刹车% / 转速 / 车速 / 摇杆X / 摇杆Y / 解锁+P 键编码 |

## 代码约定

- **命名**：函数 `模块_动作`（`ADC_SampleAll`），全局 `g_` 前缀，文件内静态 `s_` 前缀，宏全大写且数值带 `U`
- **格式**：S32K 侧 LF + 4 空格，G474 侧跟随 ST 的 CRLF + 2 空格；Allman 大括号；只用 `/* */`；行宽 ≤100
- **生成码不手改**：`GearShift_Stateflow.*` 和 CubeMX 产物只改 `USER CODE` 区。要改逻辑就改模型
- **安全逻辑必须写清三件事**：防什么、怎么动、怎么解
