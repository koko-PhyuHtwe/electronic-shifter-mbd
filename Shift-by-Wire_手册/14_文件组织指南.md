## 哪些文件可以安全删除

| 文件 | 理由 |
|------|------|
| `MATLAB/slprj/`、`*.slxc`、`*.mat`、`bundle*.js` | 构建缓存（约 2.9MB） |
| `Debug_FLASH/` 下的 `.o` / `.d` / `.elf` | 编译产物（但保留 `.args`，命令行复编译要用） |
| `STM32G474VET6/.../Drivers/` 里没用到的 HAL 模块 | 体积大头（全工程 158MB） |
| `S32K144/.../Debug_FLASH/src/*.d` | 依赖文件，重新编译会生成 |

## 哪些文件绝对不能删

1. `MATLAB/GearShift_Stateflow.slx` —— 模型唯一原件。
2. `board/sdk_project_config.h` —— 所有外设配置的入口，删了编译全崩。
3. `board/FreeRTOSConfig.h` —— 优先级和堆配置，直接影响调度行为。
4. `src/GearShift_Stateflow.c` —— 即便能重新生成，也要保证仓库里有一份可编译的。

## 命名与目录约定

- **模块前缀**：`sbw_` 表示"本项目自写的业务模块"，与 NXP/ST 生成文件（`peripherals_*`、`MX_*`、`board/`）区分开。
- **生成文件不手改**：`GearShift_Stateflow.*`、`board/clock_config.*`、`board/peripherals_*` 都是生成的。唯一例外是 `pin_mux.c`（改上下拉），因为配置工具的 UI 不好用。
- **一行一个职责**：`rtos.c` 里每个任务函数只做一件事，不做嵌套调用，方便定位问题。
- **命名**：函数 `模块_动作`（`ADC_SampleAll`）、全局量 `g_` 前缀、文件内静态量 `s_` 前缀、宏全大写且数值带 `U` 后缀。
- **格式**：S32K 侧 LF + 4 空格，G474 侧跟随 ST 的 CRLF + 2 空格；大括号 Allman 风格；只用 `/* */`，不用 `//`；行宽 ≤100。

## 编译产物与 `.args`

`Debug_FLASH/src/GearShift_Stateflow.args` 是 S32DS 生成的编译参数文件（include 路径、宏定义、优化选项）。它的用途是**不开 IDE 也能编译单个文件**：

```powershell
cd S32K144/freertos_s32k144/Debug_FLASH
arm-none-eabi-gcc.exe @src/GearShift_Stateflow.args -o out.o ..\src\rtos.c
```

这在快速验证语法错误时非常有用——IDE 启动要 30 秒，命令行编译 2 秒。
