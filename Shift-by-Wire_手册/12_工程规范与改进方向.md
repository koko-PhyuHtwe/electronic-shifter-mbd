## 代码规范

### 命名

| 前缀/形式 | 含义 | 例 |
|-----------|------|-----|
| `g_` | 全局变量 | `g_current_gear` |
| `s_` | 文件内静态变量 | `s_throttle` |
| `vTask_` | FreeRTOS 任务函数 | `vTask_Gear_Logic` |
| `MX_` | CubeMX 生成 | `MX_FDCAN2_Init` |
| `sbw_` | 本项目自写模块 | `sbw_adc.c` |
| 全大写 | 宏 | `ADC_DEAD_LOW` |
| `Module_Function` | 模块内函数 | `ADC_ToStickPos` |

### 三条硬规则

1. **跨任务共享的变量必须 `volatile`**。当前全是 8/16 位整数，读写原子；若将来加结构体，必须改用队列。
2. **ISR 里只做搬运，不做业务**。CAN 中断只入队，HMI 中断只填环形缓冲。
3. **极性、阈值、周期一律宏定义在头文件**，不写魔法数字。`git diff` 要能一眼看出"改了哪个阈值"。

### 编译零警告

S32K 侧 9 个源文件用 `arm-none-eabi-gcc` 单独编译全部 0 warning。命令行复编译方法见 README。**提交前必须零警告**——警告里藏着真实的类型截断和未初始化变量。

## 改进路线图

### 短期（P4 收尾，1~2 天）

1. ~~**0x180 加车速字节**~~：已完成（`B4 = vehicle_speed` + G474 侧重启检测与拒绝执行）。
2. ~~**启用 S32K WDOG**~~：代码已完成（`sbw_wdog.c`，1.0s，心跳任务五任务活体检测后喂），**当前 `WDOG_ENABLE` 还是 `0U`**——排查复位循环时关的，稳定后改回 `1U` 并跑一遍故障注入。
3. **跑完动力软切的 A/B/C 测试**：拔 CAN 软切、插回不自动恢复、松脚重踩恢复。
4. **接收侧校验 life_counter**：连续 3 次不 +1 → 计一次通信异常（G474 侧已用于重启检测，S32K 侧尚未做）。
5. **复位原因计数**：后备寄存器存上电次数，10 分钟内 >3 次进锁定维护态。

### 中期（P4.5，1 周）

6. **加舵机反馈电位器**：接到 G474 ADC1 IN1，`g_adc_buffer[0]` 与目标角度比较，偏差 >5° 持续 200ms → `STATUS_SERVO_FAULT`。
7. **加 DTC 表**：至少 6 条（通信丢失、超时、舵机偏差、摇杆开路、欠压、看门狗复位）。通过 HMI 或调试串口读。

> status 位回传已经做完了：`0x280.B2` 的 bit1/bit3/bit4/bit5 在 S32K 屏上分别显示为 `EXEC LOCK` / `PWR CUT` / `NO DRIVE` / `BRAKE CUT`。

### 长期（P5）

8. **CAN FD 升级**：把载荷从 7 字节扩到"全部原始 ADC + 诊断码 + 时间戳"，周期从 10ms 降到 5ms。
9. **E2E 保护**：CRC8 + 计数器 + DataID，符合 AUTOSAR E2E Profile 1/2。
10. **Bootloader**：复用已完成的 UDS Bootloader 工程（`S32K144_UDS_Bootloader`），加 OTA 刷写。
11. **ASIL 分析**：做 HARA，识别"非预期换入 P"的 ASIL 等级，反推安全机制。

## 量产还差什么（面试常问）

如果问"这个项目离量产还有多远"，按这个顺序答：

1. **功能安全**：当前无 HARA、无 FMEA、无安全手册。至少要识别出"非预期换挡"的 ASIL 等级，并证明现有的互锁与超时机制能满足。
2. **E2E 通信保护**：CAN 硬件 CRC 不够，需要应用层 CRC + 计数器，能检出"内容正确但顺序错乱"的帧。
3. **传感器冗余**：摇杆单路模拟量，一路断线就失去输入。量产需要双路互检或数字编码器。
4. **执行器闭环**：舵机必须带位置反馈，"指令=实际"才能被证明。
5. **诊断与可维护性**：DTC、冻结帧、UDS 服务（0x19/0x22/0x2E）、Bootloader。
6. **环境与 EMC**：温度循环、振动、ESD、BCI。台架上跑通不代表车上能跑。
7. **软件过程**：MISRA C、单元测试覆盖率、静态分析（Polyspace/Coverity）、需求可追溯性。

## 这个项目真正证明了什么

不是"我会用 FreeRTOS"，而是：

- **能把一个 Simulink 模型变成两片 MCU 上跑起来的实物**——闭环从建模到执行器。
- **能在没有逻辑分析仪、只有万用表和串口屏的条件下定位问题**——坑 #4 的两天和坑 #6 的"没烧录"。
- **知道哪里没做完，以及为什么没做完**——这份清单本身就是工程能力的证据。
